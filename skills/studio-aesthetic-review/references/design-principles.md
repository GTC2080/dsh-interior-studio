# 构图与设计证据卡

本资料将公开界面设计方法中的通用视觉原则改编用于实体空间与物件。来源与许可见 [NOTICE](../../../legal/aesthetic-library/NOTICE.md)。网页布局、动画或CSS数值不直接等于空间设计规则。

## 从语境得到设计语言

把对象、受众、使用方式和真实内容作为设计起点。先说明应让人识别和感受到什么，再选择轮廓、比例、字形、颜色和材料。一个可以不改任何内容就放到另一行业的方案，通常缺少本项目的识别性。

辨认“精修”和“重设计”的区别。精修改清晰度、对齐、材料尺度或局部收口；重设计需要重新建立整体构图与主次关系。不能接到重设计任务后仍只在旧底板上换字或添加装饰。

## 用关系而非风格名称设计

比较至少两个实质不同的方向：焦点在哪里，轮廓如何组织，信息怎样被看见，留白与密度如何分配，近景细节支持什么主题。不要把候选缩减为同一构图的不同配色，也不要用“现代、极简、豪华”等词代替可见选择。

一次主张应贯穿整体与细节。字体、形体、边缘、纹理和照明可以有变化，但变化需要承担明确作用。少做或多做都可能正确，理由必须来自需求，不能由固定审美模板决定。

## 以实际画面审稿

先看完整轮廓与主要焦点，再看中景层级，最后看近景材料与收口。同一方案换到正视、斜角和近景后仍应成立；只有某个机位好看、别的角度暴露缺失，不能宣称设计完成。

比较时保持相同输出尺寸和相近机位、光照条件。把设计差异与曝光、裁切、贴图缺失等技术问题分开。先记录设计判断，再读取技术检查结果；没有错误日志不是审美证据。

## 参考卡格式

每张卡只记录一项有迁移价值的思路：

| 字段 | 内容 |
| --- | --- |
| 来源 | 实际打开的公开页面、作者、日期或本地客户材料页序；保留许可/使用边界 |
| 语境 | 面向谁、承担什么用途、观察距离和限制 |
| 可见特征 | 对应画面位置、比例关系、信息层级、材料或光的处理 |
| 判断 | 为什么适合该语境；和一种可行替代相比取舍是什么 |
| 迁移 | 本项目可以采用的关系或方法 |
| 不照搬 | 不能复制的品牌素材、场地条件或不适用的风格约定 |

没有看过来源就不写“参考了”；没有实际像素就不写“画面清楚”。只有用得到的卡进入当前任务，不建立无界的图片仓库或第二份技能注册表。
