# Blender 制作与回写

本资料用于实际制作和导入精细物件。工具名、参数与资源预算以当前 PTC SDK 和 studio_context 为准，不要求用户启动 Blender、安装依赖、写脚本或操作终端。

## 后台制作

- 使用 `context.modeling.refinement.blenderExecutable` 给出的随包程序。用 PTC 的现有文件/终端能力，在有归属标记的临时目录写脚本；运行 `--background --factory-startup --disable-autoexec`，设置有限超时并处理取消/非零退出。
- 设置 `PYTHONDONTWRITEBYTECODE=1`，将 `BLENDER_USER_CONFIG`、`BLENDER_USER_SCRIPTS`、`BLENDER_USER_EXTENSIONS`、`XDG_CACHE_HOME` 都指向本轮临时目录。不下载必需组件、不更改用户 Blender 偏好，也不创建另一份应用运行时。
- 长度使用米。记录对象实际尺寸、变换、底高及承托位置；应用需要保留的修改器并正确处理法线。平滑曲线使用满足近景轮廓的采样，不为提高面数而盲目细分。
- 材质使用可导出的 Principled BSDF 和图像 UV；程序化纹理先烘焙成图片。导出静态 GLB，图片全部内嵌；不把未导出的节点、修改器、动画或骨骼称为保留。工程接口不接收 blend 文件。
- 导出后重开 GLB，核对尺寸、朝向、孔洞、材质槽、内嵌图片与需要保留的细节。仅检查制作中的 blend 不能证明导出的模型相同。工具会继续检查文件与资源预算，不能跳过或规避。

## 更新正式工程草案

所有 studio 工具结果先 `JSON.parse`，在程序内筛选完整值，仅向上下文返回必要摘要。操作同一工程时串行提交，使用最新 expectedRevision；已有待确认草案时继续带最新 drawingId。

- `studio_refine.models` 给出实际 GLB path、稳定 key、label、制作/许可来源 source、底面中心 position 和 XYZ 旋转度数。导入会把源模型底面中心归零，远处的原点和文件内偏移不能代替目标位置。scale 只做统一单位换算，不能分别缩放三轴掩盖错误比例。
- 同 key 替换保留对象 ID；将一组粗占位换成精细对象时，准确列出 removeKeys，避免两套模型重叠。不要移除未要求改变的结构，或用只含参数对象的 studio_draw 覆盖已有导入资源。
- 当前单次最多 8 个模型、30 个图片饰面、100 个移除对象。单模型最多 20 MiB、30 万顶点、20 万三角面；单图最多 16MP。批量前先读上下文预算并合理拆分，每次成功后取得新 drawingId；失败时保留正式版本，不把整批重发当作继续执行。
- 需要局部图片饰面或保存灯光/机位时，加载 studio-material-render，使用同一草案的 surfaces/presentation。导入模型本身的多材质修改后重新导入，不能假设参数构件的快捷换材质能逐面编辑任意模型。
- 工具成功返回仍是待确认草案。先审查再请用户在右侧确认；回读已确认版本及实际建模任务，不替用户授权或确认。新资源随历史版本保留，撤销和重新打开不应依赖临时文件。

## 验证与恢复

导入包络和实际 Blender 网格变换必须与锁定尺寸对应。原生审查中 importedChecked 应覆盖相关精细对象，但它只证明工具声明的顶点/变换检查，不证明内孔、接触、承载或施工节点。针对本轮实际特征补充局部几何检查，再用整体及近景图片检查可见质量。

正式出图只使用当前已确认、建模完成且 meshAudit.passed=true 的版本。运行中保留任务 ID，回读状态而不重复启动；核对 requestedViews 与实际 views。细节存在但看不见时优先调整合理机位或照明；几何不存在时回到建模修正，不能用取景隐藏问题。

失败、取消、过期草案或尺寸不符时，先回读状态，保留可继续的正式版本，说明具体问题。只清理本轮确定无用的临时资源；工程库中的已发布任务和被版本引用的文件由工程机制维护，不手工删除。
