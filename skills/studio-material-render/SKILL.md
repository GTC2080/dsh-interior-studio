# 材质、灯光与出图

先核对形体，再用表面和取景表达设计。不能靠出图掩盖遗漏、尺寸或装配错误。

造型本身过于粗略、缺少真实厚度/内腔或需精细导入时，先加载 studio-detail-modeling 完成形体；用户只说“好看一点”且意图影响本轮方案时，加载 studio-design-brief，用普通语言帮助选择观感，不要求用户提供材质或摄影参数。

需要选风格与协调材料、配色、照明时加载 studio-interior-style；实际画面出现塑料感、纹理尺度错误、过曝或接触阴影异常时加载 studio-realism，先定位原因再修改，不以提高采样或加纹理代替诊断。

## 表面决策

有图文的饰面先按实际宽高设计平面层：明确内容层级、色彩、字体可读性、裁切轮廓与留白，再映射到实体。印刷画面不应被粗略凸成圆盘或方块；立牌实体负责厚度和安装，平面稿负责图像与版式。可复用当前运行时已有的矢量/图像能力制作SVG或位图，不为导出图片重写编码器或安装新软件。先看平面稿，再看映射后的正视与近景，检查比例、翻转、遮挡和发光字可读性。没有提供的品牌原稿仍是明确占位或原创示意，不能声称还原。

- 从 context.materials 获取真实材质 ID、颜色、粗糙度及 texture 信息。根据用途区分相邻表面，保持整体色彩、质感和层次；不能用相似颜色让不同构件融为一团，也不按对象名称机械分配材质。
- 通用构件 color 是 RGB 0–1；roughness .02–1，metallic 0–1，emission 0–20。有纹理时 color 作为纹理乘色，不能把深色贴图乘成任意浅色；明确的构件粗糙度覆盖纹理粗糙度。需要准确基础色时选无图像纹理的材质，再用 color 设置。
- 目录纹理按米制 UV 和材质资源中的 metresPerRepeat 映射。需要本地图片、明确比例和方向时，调用 `studio_refine.surfaces`，指定 solid/floor 的 keys、PNG/JPEG 路径与来源、局部法向 face 和 repeat=[完整图像一次所占的u/v米数]。例如1.65×.85m竖直面，整幅铺满可用 repeat=[1.65,.85]；只使用 y- 面时其UV为局部X/Z。X向面UV为Y/Z，Z向面UV为X/Y。局部UV从该面最小角对齐，rotation用度，图片最多20MiB/16MP。该设置也生成待确认草案。
- 原生精细模型保留导入 GLB 的 UV、图片和兼容材质；程序化纹理需要先在 Blender 烘焙为图片。用标准 Principled BSDF、UV Map、Mapping 与 Image Texture 节点，避免用复杂节点网络表达 GLB 无法保留的效果。素材没有提供或来源未知时如实说明，不能把通用图案叫原画还原。
- 局部换材质需尊重当前冻结选择及表面；整件 material 会影响整件，不能把局部意图写成整件覆盖。对已有多材质目录物件先确认实际编辑粒度。
- `studio_refine.presentation` 将灯光和相机随正式版本保存。mode=studio 保留摄影补光并增加自定义灯；custom 只使用自定义灯和 worldStrength。lights 支持 area/spot/point、米制位置/目标、功率、色彩、光源尺寸和射灯锥角；功率是 Blender 参数，不是电气施工用电。发光表面不等于对周围物体照明已达标。暂未提供 HDRI 参数。
- cameras 指定稳定 key、label、position/target 和焦距。除标准总览/四面/俯视外，为有功能意义的局部增加近景与约1.5–1.7m的人眼高度视图，按用途取景，不能让关键细节都藏在遮挡后。近景不要求包含全场。lights/cameras 提供时完整替换各自列表，[]清空，不提供则保留。场景构造和机位仍须遵守真实需求。

## 生成真实图集

1. 几何、材质、灯光调整先更新 CAD 方案；纯机位调整通过studio_refine保存机位版本，按changedViews局部出图。按 `studio-space-review` 与 `studio-design-acceptance` 检查，用户确认后回读实际版本；正式任务须先完成同版本五视图 CAD，再完成三维，cadAudit.passed 与 meshAudit.passed 均为 true。不能沿用依赖不匹配的旧模型；纯机位可复用已校验的相同模型/图册，保留真实来源。旧任务无 CAD 记录或依赖摘要时先更新三维。
2. 检查已有任务，避免重复启动。正式效果图默认1080p（1920×1080）；构图与灯光试验可用preview（960×720）。只有用户明确要求才用4k。优先按context.recommendedViews生成已保存的客户视角；没有约定时才用六个标准角度。局部样板从context.renderViews选择已保存的自定义相机，每次1–12个视角。用galleryCoverage核对当前版本还有哪些角度缺失，不用外侧立面替代柜内与功能区。尺寸变为16:9后重新核对画面范围，不能假定4:3构图仍完整。
3. 保存 taskId，待任务结束后回读同一任务。queued/running 是进行中，failed 读取原因并修正，complete 才是已产出。核对实际生成版本、当前适用版本、requestedViews、views 及 meshAudit，不把单张图叫完整图集。
4. 渲染和效果图是同一交付阶段。视角、构图与材质仍需视觉验收；模型若只收到结构摘要，没有图片像素，就不能声称已目视检查画面或与原稿逐图对照。

实际网格审查检查变换、外包络、闭合性及拉伸体积，文字仅按外框。成功输出文件不能证明原画、材质观感、灯光层次或照片级效果已达标。最终给用户可查看的结果和具体剩余差异，避免空泛地说“完全还原”。

## 工具与验证衔接

为自定义相机声明subjects及purpose=overview/detail；细节可用focusPoints标出必看构造，坐标应在可见实物表面，按1mm核对，不能填构件内部或孔洞中心的空点。主体占画面比例低只作提示，不能直接当作遮挡；已声明的多个主体逐个核对，不能用前面的主体遮住后面的主体来获得通过。出图前预检会定位实体内机位、主体裁切和遮挡，无主体不记通过。只改镜头时仅渲染受影响视图，保留其余图的真实来源。使用原生job完成通知，不用sleep轮询。读取每张实际PNG，生成完成仍不是画面验收。

## 保存必须交付的视图范围

把客户要求的完整立面、柜组内面、背侧通道或局部特征保存到constraints.views，不只写在相机subjects里。每项有id/source/basis/view和scope=assembly/scene/keys；framing=complete默认要求整个范围入镜，framing=detail只用于事先明确的局部图。visibleKeys列范围内必须分别可见的对象，focusPoints是实际表面上的世界XYZ。完整构造里合理隐藏的内部板件不必列为必见。

可用studio_refine.constraints更新同一CAD草案。相机仍可自由调整位置与焦距，但不能靠缩小subjects或切成detail绕过保存的完整范围；改变验收范围走已有CAD要求变更确认。所选视图逐项读取preflight.views[].fixedChecks；未检查或失败时修正，不交付。quality.views按当前有效机位证据汇总，分批出图时未出的必需视图仍待核对，已出视图保留来源。取景检查不是图片像素阅读记录，更不是审美通过。
